# V7 IPTV v0.4.1 – compatibility / stability audit (firmware 9.00 – 14.00)

Scope: the v0.4.0 code (71d0d87), no new features. Two user reports drive it:

1. **13.52 (GoldHEN v2.4b18.13 via GamerHack), official v0.4.0 PKG: crash before the UI appears.**
2. **Local Media: internal storage is listed, USB drives never are.**

## 1. USB drives not detected – root cause confirmed

v0.4.0 probed only `/mnt/usb0` … `/mnt/usb7`. An application runs in the console's file system sandbox. Inside it,
USB drives are `/usb0` … `/usb7` and `/data` is the console's `/user/data`; `/mnt/usbN` is the view from outside the
sandbox (FTP, GoldHEN, a process that escaped the sandbox).

Evidence:

- Our own hardware session 1 (commit 94c6a82): the IPTT00001 test app, launched the same way, got `opendir("/mnt")`
  = ENOENT. `/mnt` does not exist in the sandbox, so v0.4.0 could never list a USB drive. `/data` worked, which
  matches the report.
- RetroArch's PS4 frontend (`platform_orbis.c`) offers `/usb0`. EmuSuNi documents "the app's /usb0/... is
  /mnt/usb0/..., its /data/... is /user/data/..." and says that a mount point with no drive is an empty folder.

Fix (`src/media/local_media.*`):

- The candidates are `/data/`, then `/usb0..7/`, then `/mnt/usb0..7/` (the last for unsandboxed setups).
- **No duplicates.** The two views are never mixed: when any `/usbN` holds a drive, only `/usbN` roots are offered;
  `/mnt/usbN` is used only when no `/usbN` does. Within a view each drive number gives one root. A drive therefore
  appears once, even if the views ever numbered it differently.
- A USB folder with no entries counts as a mount point without a drive. It is not offered as a root, and the
  storage list says "No USB drive found". Hidden entries (`.Trashes`, `System Volume Information`) count, so a
  real drive with nothing visible is still listed. Each scan (Triangle, or Cross on the "No USB drive" row) looks
  again, so a drive that was unplugged disappears.
- Every path is classified as `ok / missing / empty / denied / not-a-folder / error (errno)` (`probeRoots`). Each
  scan logs the result, for example `data ok, usb0 empty, …, mnt/usb0 missing`.
- When no drive is found, the log also lists the names under `/` and `/mnt` and the process's file system view.
- The storage list shows one row when no drive can be opened. It reads "No USB drive found (exFAT / FAT32)" or
  "USB drive not readable (No access)". Cross on that row scans again.
- The existing protections apply unchanged to `/usbN` roots:
  - normalized paths with no `..`;
  - `within()` checks on every open;
  - symbolic links are skipped with `lstat` / `d_type`;
  - read-only access;
  - the scan caps.
- Hardened: `list()` also refuses a path whose folders below the root include a symbolic link (ELOOP) or a file
  (ENOTDIR), even when called directly with such a path. The screen never builds one (links are never listed), so
  this changes nothing visible. The root itself is a fixed system path and may be a link.
- Host tests check that a sandbox root such as `/usb3/` cannot be escaped (`/usb3/../data`, `/usb30`, links to
  `/data`, to `/` and inside the drive).
- **Privacy.** mpv writes `Playing: <path>` and the names of external subtitle files to its log. For a local file
  these lines now read `Playing: [local file]`, `[local folder]/[local name].en.srt` (`redact::maskLocalPath`). This
  affected local files since v0.4.0; the USB fix and the diagnostic checklist (which asks testers to send the log
  after playing a USB file) made it urgent.

Still needs hardware: whether `/usbN` is visible to this title on each firmware, and whether GoldHEN builds that
escape the sandbox show `/mnt/usbN` instead (both paths are handled).

## 2. 13.52 startup crash – not provable without hardware

**What runs before the first frame, in order:**

| # | Step | Firmware sensitive? |
|---|---|---|
| 0 | Process load: NEEDED modules + `sce_module/libc.prx`, `libSceFios2.prx` | Same 10 modules as pPlay. Our extra imports (`_execve`, `_wait4`, `_fstatfs`, `ftruncate`, `sceKernelGetProcessTime`, `sceSysmoduleLoadModule`, `sceSystemServiceParamGetInt`, `sceUserServiceGetInitialUser`, …) are long-standing libkernel/system exports. |
| 1 | `diag::init` (log in `/data/PS4IPTV/logs/`) | Errors are handled. Every line is flushed. |
| 2 | `sceSysmoduleLoadModuleInternal(NET)` | Same as pPlay. Return value is logged. |
| 3 | libcross2d `Renderer` → `SDL2Input` (scePad), `SDL_Init(VIDEO)` → `PS4_LoadModules` (AUDIOOUT, PAD, SYSTEM_SERVICE, USER_SERVICE) → `PS4_PigletInit`: `sceKernelLoadStartModule("/<sandbox word>/common/lib/libScePigletv2VSH.sprx")` + `scePigletSetConfigurationVSH` → EGL window/context → precompiled shaders | Disassembled `SDL_ps4piglet.c.obj`: the hard-coded binary patch of the Piglet module (fixed offsets) runs **only** with the shader-compiler hint. Our build has `OPTION_PS4_SHACC=OFF`, so no firmware-specific offsets run. SDL's own log lines (module paths, failures) go to our log. |
| 4 | App members (stores, services, image loader) | Plain C++ / file I/O |
| 5 | Fonts, clock (`sceSystemServiceParamGetInt`), libcurl/mbedTLS init, 4 worker threads | Return values are logged. |
| 6 | Profiles / settings / library / download manifest load | Damaged files are covered by host tests (new test below). |
| 7 | **Keyboard** (new in v0.4.0): `sceSysmoduleLoadModule(0x0106)`, internal fallback, module list + `sceKernelDlsym`, `sceKeyboardInit`, `sceUserServiceGetInitialUser` | The most firmware-sensitive new code: run-time module and ABI, no compile-time check. |
| 8 | Subtitle font copy, **mpv + FFmpeg + mpv GL render context** | Same as pPlay. |
| 9 | Screens, first frame. The first `keyboard.poll` (sceKeyboardOpen/ReadState) runs just before the first draw. | |

**Diagnostics added** (`src/platform/startup_state.*`, `src/platform/system_info.*`):

- Each stage is logged and written to `/data/PS4IPTV/logs/startup.txt` (build, phase, stage, skips, failed starts).
  The file holds no user data.
- The next start logs where the previous one stopped. Settings > Diagnostics > Startup check shows it too.
- The log records the system software version (`sceKernelGetSystemSwVersion`, for example `13.52`) and the file
  system view (`/data`, `/mnt`, `/mnt/sandbox`, `/system/common/lib`, sandbox word dir: yes/no).
- **Crash guard.** If the previous start of the same build died inside an optional stage (keyboard, player,
  subtitle font), the next starts skip that stage. The app opens without it instead of crashing on every launch.
  - Only a death inside an optional stage adds a skip. The app's own Exit (also before the first frame), a close
    from the PS4 menu after the first frame, a renderer failure and a death in a required stage never do. Required
    stages are only localized.
  - A skip is never permanent. It ends at the first of: a normal clean exit (the app's Exit; the next start runs
    every stage), 5 starts (`SKIP_STARTS`; the stage is then tried again), a new build, or Diagnostics > Startup
    check.
  - If a start cannot write `startup.txt`, the guard is off for that start, and a stale file is removed when it
    can be: an old record must never disable anything.
  - Stage names read back from the file are limited to the app's own list ("unknown" otherwise), so nothing from
    the file reaches the log.
- **Renderer failure.** v0.4.0 kept going after a failed SDL/GL start, then called GL through null function
  pointers (textures, shaders, mpv render context), which is a crash. Now the app logs the SDL error, sends a
  system notification (`sceKernelSendNotificationRequest`, no renderer needed) and exits cleanly.
- The keyboard module lookup caps the module count at its 256-entry buffer, so a larger count from the kernel can't
  read past it. It also NUL-terminates module names and logs each step.

**Likely causes on 13.52, in order** (unproven):

1. The keyboard library: a new run-time module/ABI path in v0.4.0. The crash guard turns a crash there into one
   crash, then starts without the keyboard.
2. Piglet / GL start under the new 13.5x jailbreak. With this build a clean failure exits with a notification; a
   crash inside SDL is localized by `stage=renderer` and SDL's log lines.
3. The jailbreak environment itself (GoldHEN 2.4b18.x on 13.5x is weeks old). If other OpenOrbis homebrew such as
   pPlay also crashes there, the cause is outside the app.

## 3. Other firmware-sensitive areas reviewed

| Area | Finding |
|---|---|
| sysmodules / runtime libs | NET is checked and logged. Keyboard is optional and now crash-guarded. Piglet: no binary patch. |
| file system paths | `/data` is fine (sandbox maps it). USB was wrong (fixed). The log/startup file degrade gracefully when not writable (tested). |
| controller / keyboard | No pad at start: re-probed every 2 s (existing). Keyboard missing: controller only (existing), now crash-guarded. |
| network start | `curl_global_init` result logged. NET module failure logged, app continues offline. |
| SDL / OpenGL / audio | Renderer failure now exits cleanly. Audio (`sceAudioOut*`) is opened by mpv only at playback. |
| FFmpeg / mpv | Init failure was already non-fatal (`Playback::available()` guards every call). It can now also be skipped by the crash guard. |
| missing optional symbols | Keyboard `sceKernelDlsym` results are checked. SDL logs a failed GL `dlsym`. |
| damaged settings / cache / profile files | New host test: 16 kinds of damage plus directories in place of files, for profiles, Stalker sidecar, settings, favorites, history and the download manifest (with their `.bak`). No crash, nothing invented. |
| shutdown / exit | Unchanged pPlay sequence. The failed-start path never deletes a half-built renderer. |
| unchecked returns / null / ABI | Module-list overflow fixed. `OrbisKernelModuleInfo` matches SDL's 352-byte size. `OrbisKeyboardData` offsets static_asserted (existing). SW version read into an oversized zeroed buffer. |

## 5. Tests

- `tests/host/test_startup.cpp` (new) covers:
  - the state file round trip and damaged or hostile content (closed stage vocabulary, optional skips only);
  - the crash-guard rules: optional stages only, same build only, counters, the skip lifetime;
  - the tracker across simulated starts and every way a session ends: death in an optional / required stage, close
    from the system, the app's Exit before and after the first frame, renderer failure, expiry after 5 starts,
    Diagnostics, a new build, a damaged file, an unwritable location, a stale read-only file, a write failing later;
  - the log never carries state-file content (addresses, logins, MACs, paths);
  - the firmware version format;
  - a damaged-data-files startup.
- `tests/host/test_localmedia.cpp`:
  - `localmedia_usb_probe_sandbox_paths_and_diagnostics`: sandbox and outside views, never mixed, every drive number
    once, empty / hidden-only / unplugged mount points, denied paths, `/` and `/mnt` names, symbolic links on a
    `/usbN` drive;
  - `localmedia_paths_never_reach_the_log`: the mpv line masking;
  - updated root-order/detection tests (drives now need an entry; 17 candidates).
- A mutation check (each guarantee broken on purpose: views mixed, link folders followed, skips kept after Exit,
  file names logged) made the matching tests fail.
- Full host suite and the ASan + UBSan variant both pass.
